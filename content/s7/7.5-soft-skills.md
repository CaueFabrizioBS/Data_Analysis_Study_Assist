## Ferramenta não é o objetivo

O time não precisa dos dados: precisa do insight que sai deles. SQL, Python e gráficos são a lupa; o objetivo é resolver o problema do negócio.

| Detetive | Analista |
|---|---|
| O crime | O problema do negócio |
| Interrogar testemunhas | Conversar com quem pediu |
| Lupa, digital | SQL, pandas, gráficos |
| Pistas | Números estranhos nos dados |
| Suspeito | Hipótese |
| Prender o culpado | Recomendação que resolve |

> [!ex] O caso das taxas de conversão
> **Pedido:** "Calcule as taxas de conversão dos anúncios."
> **Por quê?** "As newsletters estão caras e não dão resultado."
> **Onde olhar:** os e-mails são lidos no celular, segunda à tarde.
> **Pista:** no celular, o usuário vai ao checkout e a sessão cai.
> **Culpado:** o layout do celular quebrou e o botão "pagar" não aparece.
> Se o analista só calculasse todas as conversões em todos os aparelhos, os números estariam certos e o botão continuaria quebrado.

## Os 6 passos de uma tarefa

```fluxo
1 Quem → 2 Para quê → 3 Quais dados → 4 Registrar → 5 Rascunho → 6 Entregar
```

1. **Quem é o cliente?** Quem vai usar o resultado define o que vai nos gráficos e o tom.
2. **Para quê?** "Onde investir mais" e "qual canal cortar" pedem análises diferentes.
3. **Quais dados?** O nível de detalhe costuma estar escondido: pediram "por mês", mas precisam "por produto e dia da semana".
4. **Registrar o escopo**, mesmo que digam que não precisa: cliente, objetivo, pergunta, dados, período, detalhe, formato, prazo e o que fica de fora. É o contrato.
5. **Rascunho → feedback → revisão.** Mudar no meio é barato; no fim é caro.
6. **Entregar e fechar** o ticket ou o e-mail.

> [!dica] Antes de encerrar a reunião
> Repita o pedido: "Então você quer X, por Y, de tal período, em tal formato, até tal dia. É isso?". Se a pessoa disser que sim, escreva e mande por e-mail.

## Quando pedem para refazer

- **Emoções:** respire antes de responder; refazer no fim é perda de tempo para os dois. Proponha mostrar um rascunho no meio do caminho da próxima vez.
- **Reflexão honesta:** a tarefa foi bem feita? Faltou perguntar algo? O escopo estava escrito? O código estava pronto para mudar?
- **Código flexível:** deixe o que pode mudar (período, nível de data, filtros) num lugar só. Trocar `DATE_TRUNC('month', ...)` por `'day'` é uma palavra.

## Soft skills

| Habilidade | No trabalho |
|---|---|
| Curiosidade | Perguntar "por quê?" antes do "como" |
| Escuta ativa | Repetir o pedido com suas palavras |
| Pensamento de detetive | Pista → hipótese → teste → conclusão |
| Organização | Escopo escrito, rascunho mostrado, ticket fechado |
| Inteligência emocional | Receber crítica sem brigar |
| Autocrítica | "O que eu poderia ter perguntado?" |

## Os 5 porquês

Pergunte "por quê?" até chegar na causa (costuma aparecer em 3 a 5 perguntas). Comece pelo fato, cada resposta tem que ser verificável nos dados, e o tom é de curiosidade, não de culpa.

```fluxo
Pagamentos caíram → newsletters não convertem → quem lê no celular abandona o checkout → o botão não aparece → o layout quebrou
```
