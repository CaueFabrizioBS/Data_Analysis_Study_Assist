Toda análise passa pelas mesmas 6 fases. Pular uma delas causa a maioria dos números errados. O caminho não é reto: na fase 4 ou 5 você pode achar um problema novo e voltar para a 2.

```fluxo
1 Conhecer → 2 Investigar → 3 Limpar → 4 Juntar → 5 Analisar → 6 Entregar
```

## 1. Conhecer o banco

- Olhe o diagrama ER: tabelas, PKs, FKs, ligações sem linha ([7.4](#c7-4)).
- Espie e conte: `SELECT * FROM products LIMIT 5;` e `SELECT COUNT(*) FROM products;`. Anote o total: é o ponto de controle da fase 4.
- Confira os tipos:

```sql
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'products';
```

> [!regra] A pergunta mais importante
> "O que é **uma linha** desta tabela?" Em `transactions`, uma linha é um produto dentro de uma compra. Por isso "número de compras" é `COUNT(DISTINCT id_transaction)`.

## 2. Investigar (só olhar, ainda sem consertar)

| Sintoma | Consulta |
|---|---|
| Vazio | `COUNT(*) - COUNT(col)` |
| Repetido | `GROUP BY id HAVING COUNT(*) > 1` |
| Escrita diferente ("Milk" × "milk") | `GROUP BY col` |
| Número impossível (preço negativo) | `MIN(col)`, `MAX(col)` |
| Tipo errado | `CAST` dá erro |
| Período coberto | `MIN(date::date)`, `MAX(date::date)` |

Saída da fase: uma lista de problemas ("weight: 1 vazio e 1 texto; category: Milk e milk").

## 3. Limpar e transformar

No SQL de análise você **não altera a tabela**: a limpeza fica dentro da consulta.

| Problema | Ferramenta |
|---|---|
| Número guardado como texto | `CAST`, `::real` |
| Vazio que deve virar valor | `COALESCE(col, 0)` |
| Criar faixas | `CASE WHEN` |
| Maiúsculas e espaços | `LOWER(TRIM(col))` |
| Texto parecido | `LIKE`, `ILIKE` |
| Data com hora / em texto | `::date`, `DATE_TRUNC`, `EXTRACT` |
| Valor impossível | `WHERE price > 0` |
| Linha copiada | `DISTINCT` |

**NULL tem três saídas:** remover (`IS NOT NULL`), preencher (`COALESCE`, só quando o valor é verdadeiro: "sem desconto" = 0) ou manter (AVG e SUM já ignoram). Trocar peso vazio por 0 puxa a média para baixo.

```sql
SELECT categoria, COUNT(*)
FROM (SELECT LOWER(TRIM(category)) AS categoria, weight::real AS peso
      FROM (SELECT DISTINCT * FROM products) AS p
      WHERE weight IS NOT NULL) AS limpo
GROUP BY categoria;
```

## 4. Juntar

| Eu quero | Use |
|---|---|
| Só o que tem par nas duas | `INNER JOIN` |
| Tudo da principal, com ou sem par | `LEFT JOIN` |
| O que **não** tem par ("nunca") | `LEFT JOIN` + `WHERE ... IS NULL` |
| Empilhar listas | `UNION` / `UNION ALL` |

**Conte antes e depois do JOIN.** Igual: ligação certa. Maior: duplicou (faltou condição no ON). Menor: sumiu linha (era para ser LEFT?).

> [!erro] Armadilhas do JOIN
> - INNER depois de um LEFT apaga os NULL que o LEFT guardou.
> - No LEFT JOIN, filtro da tabela da direita no `WHERE` vira INNER. Coloque no `ON`.
> - Coluna com o mesmo nome nas duas tabelas sem prefixo dá erro "ambiguous".
> - UNION com colunas em ordem diferente não dá erro: embaralha em silêncio.

## 5. Analisar: 8 receitas

```sql
-- 1. Total por grupo: compras por mês
SELECT DATE_TRUNC('month', date) AS mes, COUNT(DISTINCT id_transaction) AS compras
FROM transactions GROUP BY 1 ORDER BY 1;

-- 2. Top N: 10 produtos mais vendidos
SELECT p.name, COUNT(*) AS vendas
FROM transactions t JOIN products p ON p.id_product = t.id_product
GROUP BY p.name ORDER BY vendas DESC LIMIT 10;

-- 3. Filtro de grupo: preço médio acima de 4
... WHERE ps.price > 0 GROUP BY p.name HAVING AVG(ps.price) > 4;

-- 4. Variação: quanto cresceu em relação ao mês anterior
SELECT mes, compras, compras - LAG(compras) OVER (ORDER BY mes) AS variacao
FROM (...) AS m;

-- 5. Top por grupo: 3 mais caros de cada categoria
SELECT * FROM (
  SELECT p.category, p.name, ps.price,
         RANK() OVER (PARTITION BY p.category ORDER BY ps.price DESC) AS rk
  FROM ...) AS x
WHERE rk <= 3;

-- 6. Participação %: cada loja no total
SELECT s.name_store, SUM(ps.price) * 100 / SUM(SUM(ps.price)) OVER () AS pct
FROM ... GROUP BY s.name_store;

-- 7. Acumulado dia a dia
SUM(compras) OVER (ORDER BY d ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)

-- 8. O que falta: lojas que nunca venderam
SELECT s.name_store FROM stores s
LEFT JOIN transactions t ON t.id_store = s.id_store
WHERE t.id_store IS NULL;
```

> [!regra] Montando qualquer análise
> 1. Qual é a **caixa** (o "por")? → GROUP BY ou PARTITION BY.
> 2. Qual é a **conta**? → a função.
> 3. Filtro de **linha** ou de **grupo**? → WHERE ou HAVING.
> 4. Precisa comparar com outra linha? → janela (LAG, RANK, SUM OVER).

`GROUP BY 1` e `ORDER BY 1` são atalhos para "a primeira coluna do SELECT".

## 6. Entregar

**Antes de entregar, confira:**

- O número de linhas faz sentido (1 por loja? 1 por mês?).
- Um total que você conhece bate.
- Não apareceu NULL onde não devia (veio de um LEFT JOIN?).
- "Compras" contou `DISTINCT id_transaction`.
- O período é o pedido (data com hora: use `::date`).
- Divisão de inteiros não cortou casas.
- O resultado responde **a pergunta**.

Nomes claros com `AS` (sem espaço nem acento), `ROUND` nos decimais e `ORDER BY` no final.

**Levando para o pandas:**

```python
from sqlalchemy import create_engine
engine = create_engine('postgresql://user:senha@host/banco')
df = pd.read_sql(query, engine)
```
