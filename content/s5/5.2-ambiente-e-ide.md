## Ambiente virtual

Cada projeto precisa de versões específicas de bibliotecas. Um **ambiente virtual** é uma instalação isolada do Python com só os pacotes daquele projeto. Assim, atualizar o pandas num projeto não quebra outro.

Os seus projetos usam `venv` (pasta `.venv` ou `venv` dentro do projeto). O curso também mostra o **conda**.

| Tarefa | venv + pip | conda |
|---|---|---|
| Criar | `python -m venv .venv` | `conda create --name myenv python=3.9` |
| Ativar | `.venv\Scripts\activate` (Windows) / `source .venv/bin/activate` | `conda activate myenv` |
| Instalar | `pip install pandas` | `conda install -n myenv scipy=0.15.0` |
| Exportar | `pip freeze > requirements.txt` | `conda list --export > requirements.txt` |
| Recriar | `pip install -r requirements.txt` | `conda env create --name myenv --file ENV.yml` |

## requirements.txt

Lista as bibliotecas e versões do projeto, uma por linha:

```text
pandas==1.3.1
scipy==1.6.2
streamlit==1.12.2
```

Quem clonar o projeto roda um comando e tem o mesmo ambiente. Todo projeto entregue deve ter um.

## IDE

IDE (*integrated development environment*) junta editor de código, terminal, depurador, testes e controle de versão num lugar só. O **VS Code** (Microsoft) é o mais usado; tecnicamente é um editor que vira IDE com extensões.

> [!comp] Jupyter × VS Code
> - Jupyter: explorar dados, ver gráfico e tabela logo abaixo do código, contar a história da análise.
> - VS Code: scripts `.py`, apps (como o Streamlit do car-market-explorer), projetos com vários arquivos. Ele também abre notebooks.
