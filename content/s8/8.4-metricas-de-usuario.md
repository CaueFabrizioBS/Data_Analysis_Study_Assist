## DAU, WAU e MAU

Quantas pessoas **diferentes** usaram o produto num período. Medem o tamanho do público ativo, não quanto ele paga.

| Sigla | Significa |
|---|---|
| DAU | *Daily Active Users*: usuários únicos por dia |
| WAU | *Weekly Active Users*: por semana |
| MAU | *Monthly Active Users*: por mês |

> [!erro] DAU × 7 não dá o WAU
> Uma semana com 4 pessoas que entram em dias diferentes pode somar 9 acessos diários. O WAU é **4**: quem volta em vários dias conta uma vez só na semana.

São chamadas de **métricas de vaidade**: quase sempre sobem (app mais velho acumula gente) e reagem devagar ao que se faz no produto. Lançou uma função nova hoje? O MAU nem se mexe. Servem para mostrar o tamanho e o crescimento do público, e são a base do fator de grude.

## Fator de grude (sticky factor)

```formula
Sticky (semana) (%) = DAU // WAU
Sticky (mês) (%) = DAU // MAU
```

De quem usou o app na semana, quantos aparecem num dia comum? Perto de 100% é hábito forte. Se cada um vem só 1 dia por semana: 1/7 ≈ 14%. No app de entrega por drone: DAU 1.536, WAU 8.297 → **18,5%**.

`DAU/WAU` para apps de uso frequente (mensagens, redes sociais). `DAU/MAU` para uso espaçado (entrega, banco).

> [!comp] Fator de grude × retenção de coorte
> A retenção acompanha **um mesmo grupo** semana a semana. O fator de grude é uma **foto** do público geral, misturando novos e antigos.

```python
users_data['session_year'] = users_data['session_start_ts'].dt.year
users_data['session_month'] = users_data['session_start_ts'].dt.month
users_data['session_week'] = users_data['session_start_ts'].dt.week
users_data['session_date'] = users_data['session_start_ts'].dt.date

dau_total = users_data.groupby('session_date').agg({'id': 'nunique'}).mean()
wau_total = users_data.groupby(['session_year', 'session_week']).agg({'id': 'nunique'}).mean()
mau_total = users_data.groupby(['session_year', 'session_month']).agg({'id': 'nunique'}).mean()

sticky_wau = dau_total / wau_total * 100
```

`nunique` conta pessoas, não sessões. `mean()` transforma um número por período em um só. Ano junto com semana e mês: a semana 19 existe todo ano.

## Sessões por usuário

Sessão é tudo que a pessoa faz entre abrir e fechar o app.

```formula
Sessões por usuário = nº de sessões // nº de pessoas diferentes
```

Perto de 1: a maioria abre uma vez e não volta. Quanto maior, mais o app faz parte da rotina.

```python
spu = users_data.groupby(['session_year', 'session_month']).agg({'id': ['count', 'nunique']})
spu.columns = ['n_sessions', 'n_users']
spu['sess_per_user'] = spu['n_sessions'] / spu['n_users']
```

## ASL: duração média da sessão

```python
users_data['session_duration_sec'] = (
    users_data['session_end_ts'] - users_data['session_start_ts']).dt.seconds
```

ASL alto é bom em jogos, streaming e redes sociais. Num despertador, sessão curta é o esperado: lá vale mais olhar a retenção. Quando o ASL cai, investigue (as sessões no celular ficaram curtas? a versão mobile está difícil?).

> [!regra] Média, mediana ou moda?
> Olhe o formato antes (`hist(bins=50)`). Em sino, média e mediana dão quase o mesmo. Com pico e cauda longa, a média engana: no app de drones, a maioria das sessões dura 60 s, mas a média dá 454 s. Use a **mediana**, ou a **moda** quando os valores se repetem muito (os horários foram arredondados para o minuto).

## Frameworks de métricas

**HEART** (Google), foco na experiência:

| Letra | Métrica | Pergunta |
|---|---|---|
| H | *Happiness* (felicidade) | Gostam do produto? |
| E | *Engagement* (engajamento) | Com que frequência usam? |
| A | *Adoption* (adoção) | Quantos usuários novos chegam? |
| R | *Retention* (retenção) | Quantos continuam? |
| T | *Task success* (sucesso da tarefa) | A ação objetivo foi concluída? |

Para cada letra: **objetivo** (o que o produto quer) → **sinal** (o que muda no comportamento) → **métrica** (como virar número).

**AARRR** ("métricas pirata"), foco no caminho até a receita, como um funil:

```fluxo
Aquisição → Ativação → Retenção → Referência → Receita
```

- **Aquisição:** de onde vêm os clientes?
- **Ativação:** fizeram a ação objetivo logo no começo? No app de drones, é fazer o primeiro pedido; abrir o app não conta.
- **Retenção:** quantos continuam?
- **Referência:** recomendam?
- **Receita:** como aumentar o que entra?

## Detecção de anomalias

Anomalia é um salto ou queda fora do padrão. O dado mostra que algo aconteceu; descobrir o quê exige olhar o negócio.

```fluxo
Coletar e calcular → Visualizar → Isolar a fatia estranha → Procurar o motivo → Concluir
```

> [!erro] A primeira leitura engana
> Atividade disparou? É quase Natal. Sessões ficaram curtas? Uma atualização tirou a tela que explicava o serviço.
> Suspeitos de sempre: sazonalidade, feriados e problemas técnicos. Confira os três antes de qualquer teoria.

**Fatiar para achar onde crescer:** uma conversão geral "boa" pode esconder pedaços muito ruins (noite 2% contra dia 6%; mobile 2% contra app 7%). Ali um ajuste pequeno rende mais.

## Y.Metrica

Ferramenta de análise web da Yandex, parecida com o Google Analytics. Sabe idade, interesses, cidade, dispositivo e navegador de quem visita.

| Pergunta | Onde olhar |
|---|---|
| A página de entrada funciona? | Relatórios por página |
| O que o usuário faz e onde trava? | Session Replay (grava a sessão) |
| Que partes da página ninguém vê? | Mapa de rolagem e de calor |
| Por que não terminam o cadastro? | Analítica de formulários |

**API de Logs:** o painel mostra dados agregados; a API baixa os dados brutos (uma linha por visita). Fluxo: token → `evaluate` (GET: cabe?) → `logrequests` (POST: cria o pedido) → espera o status virar `processed` → baixa as partes → `pd.concat`.

```python
status = 'created'
while status == 'created':
    time.sleep(60)                           # APIs limitam requisições
    r = requests.get(URL_STATUS, headers=HEADERS)
    if r.status_code == 200:
        status = json.loads(r.text)['log_request']['status']

tmp_dfs.append(pd.read_csv(StringIO(r.text), sep='\t'))   # StringIO: texto se passa por arquivo
```

> [!erro] O token é pessoal
> Não deixe o token escrito no notebook que vai compartilhar. Guarde num arquivo separado ou numa variável de ambiente.

> [!ex] Anúncio ou busca: quem fica mais?
> Tire as visitas de 0 s, separe por fonte, compare os histogramas e teste: `st.ttest_ind(ad, organic)`. Anúncio: 60 s em média; busca: 637 s; valor-p ≈ 0. Quem chega pela busca veio procurar aquilo. Vale checar se o anúncio está levando a pessoa certa.

## Bônus: deixar o pandas mais leve

Texto (`object`) é o tipo mais pesado.

```python
df = pd.read_csv('visits.csv', nrows=500)      # prova numa amostra
df.info(memory_usage='deep')                   # peso real das colunas de texto

df = pd.read_csv('visits.csv',
                 dtype={'Device': 'category'},               # poucos valores repetidos
                 parse_dates=['Start Ts', 'End Ts'])         # datas já como datetime
```

Em 500 linhas: 109,7 KB → 16,2 KB. `category` não compensa quando quase todo valor é diferente (ids, URLs).
