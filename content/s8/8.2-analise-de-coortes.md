## O que é uma coorte

Um grupo de pessoas que fez **o mesmo evento** no **mesmo período**.

```fluxo
Evento + Período = Coorte
```

| Evento | Período | Coorte |
|---|---|---|
| Se cadastrou | Maio de 2019 | Cadastrados em maio de 2019 |
| Fez o 1º pedido | 5 a 11/08/2019 | Primeira compra nessa semana |
| Fechou contrato | 1º trimestre de 2018 | Empresas com contrato no 1T 2018 |

O período decide o grupo: nascidos em 1986 e 1987 são coortes diferentes por ano e a mesma por década. Uma pessoa está em várias coortes ao mesmo tempo, conforme o período da análise.

> [!comp] Coorte × categoria
> "Visitantes que moram em Denver" é só uma **categoria** (segmento): diz quem, mas não o que fizeram nem quando. Teste: dá para dizer **o que** o grupo fez e **quando**? Se os dois, é coorte.

Para que serve: acompanhar o mesmo grupo no tempo ("dos que entraram em março, quantos seguiam ativos em junho?") e gerar hipóteses. A análise é **retrospectiva**: raramente prevê o futuro, que depende de sazonalidade, concorrência e outros fatores externos.

## Montando coortes em pandas

A tabela de pedidos tem uma linha por pedido. A ideia é colocar, ao lado de cada pedido, a data do **primeiro** pedido daquele cliente: essa é a coorte dele.

```python
# 1. Primeira compra de cada cliente
first_order = orders.groupby('customer_id')['order_date'].min()
first_order.name = 'first_order_date'        # evita conflito com a coluna order_date

# 2. Devolver para cada pedido
orders = orders.join(first_order, on='customer_id')

# atalho para 1 + 2:
orders['first_order_date'] = orders.groupby('customer_id')['order_date'].transform('min')

# 3. Cortar as duas datas no mês
orders['first_order_month'] = orders['first_order_date'].astype('datetime64[M]')
orders['order_month'] = orders['order_date'].astype('datetime64[M]')

# 4. Uma linha por coorte
orders.groupby('first_order_month').agg(
    {'order_id': 'nunique', 'customer_id': 'nunique', 'revenue': 'sum'})
```

> [!dica] Versões do pandas
> `astype('datetime64[M]')` funciona no pandas do curso. Em versões novas, use `dt.to_period('M').dt.to_timestamp()`.

`customer_id · nunique` é o tamanho da coorte (clientes novos daquele mês). Pedidos e receita somam **todos os meses** desde a entrada.

> [!erro] Receita total não compara coortes
> A coorte de dez/2010 teve 12 meses para comprar; a de dez/2011, poucos dias. Receita maior ali é só mais tempo, não clientes melhores.

## Valor absoluto × relativo

- **Absoluto:** contagem ou soma, sem divisão (receita, número de clientes).
- **Relativo:** um absoluto dividido por outro (receita ÷ clientes = receita por usuário). As partes precisam ter ligação: receita ÷ compras faz sentido; tamanho da compra ÷ passos até a loja, não.

## Tabela de coortes

```python
orders.pivot_table(index='first_order_month',   # linhas: uma por coorte
                   columns='order_month',        # colunas: mês da compra
                   values='customer_id',
                   aggfunc='nunique')            # clientes ativos naquele mês
```

```desenho coorte-escada
números inventados, só para mostrar a escada
```

Trocando `values` e `aggfunc`, a tabela mede outra coisa: `order_id · nunique` (pedidos), `revenue · sum` (receita).

Como ler: cada **linha** é a vida de uma coorte; a primeira célula é o tamanho dela; células vazias formam uma escada (a coorte ainda não existia). Cada **coluna** é um mês do calendário.

- **Nas linhas:** o normal é cair depois do primeiro mês. Uma coorte que volta a subir chama atenção (promoção?).
- **Nas colunas:** se **todas** caem no mesmo mês, o motivo é o calendário (sazonalidade).

> [!erro] Comparar coortes de idades diferentes
> Em junho, a coorte de jan/2019 tem o menor número. Não prova que é pior: é a mais velha. Compare na **mesma idade**: no 2º mês de vida, jan manteve 86% e fev 85%.

## Receita por usuário e tempo de vida

```python
g = orders.groupby(['first_order_month', 'order_month']).agg(
        {'revenue': 'sum', 'customer_id': 'nunique'})
g['revenue_per_user'] = g['revenue'] / g['customer_id']     # soma primeiro, divide depois
```

Pivotada pelo mês do calendário, a mesma idade fica na diagonal. A solução é o **tempo de vida da coorte**: quantos meses desde o mês de entrada (o mês de entrada é **0**).

```python
import numpy as np
g = g.reset_index()
g['cohort_lifetime'] = (
    (g['order_month'] - g['first_order_month']) / np.timedelta64(1, 'M')
).round().astype('int')

g['first_order_month'] = g['first_order_month'].dt.strftime('%Y-%m')   # só aparência
revenue_per_user_pivot = g.pivot_table(index='first_order_month',
                                       columns='cohort_lifetime',
                                       values='revenue_per_user', aggfunc='mean')
```

Agora cada coluna compara as coortes na mesma idade. A subtração dá dias; dividir pelo mês do numpy (média de 30,44 dias) dá fração, por isso o `round`.

## Mapa de calor

Pintar as células faz os padrões saltarem aos olhos.

```python
import seaborn as sns
from matplotlib import pyplot as plt

plt.figure(figsize=(13, 9))
plt.title('Volume Médio de Compras dos Clientes')
sns.heatmap(revenue_per_user_pivot, annot=True, fmt='.1f',
            linewidths=1, linecolor='gray')
```

| Parâmetro | Faz |
|---|---|
| `annot=True` | Escreve o número na célula |
| `fmt='.1f'` | 1 casa decimal (`'.1%'` para porcentagem) |
| `linewidths`, `linecolor` | Linha entre as células |

> [!erro] Célula escura isolada
> Pode ser efeito de poucos clientes fazendo pedidos grandes. Confira quantos há antes de concluir.

## Retenção e cancelamento

O exemplo é o Minder, um app de encontros: quem continua procurando e quem desistiu.

```formula
Retenção (%) = ativos na semana n // ativos na semana 0
Razão = ativos na semana n // ativos na semana n−1
Cancelamento (%) = (razão − 1) × 100
```

| Semana | Ativos | Retenção (÷ semana 0) | Cancelamento (÷ semana anterior) |
|---|---|---|---|
| 0 | 1.000 | 100% | |
| 1 | 700 | 70% | −30% |
| 2 | 500 | 50% | −28,6% |
| 3 | 550 | 55% | +10% (alguns voltaram) |

Retenção nunca é negativa. O cancelamento negativo é gente saindo; positivo, gente voltando.

**Coortes semanais** (em app, esperar um mês para decidir é demais). A semana é identificada pela segunda-feira:

```python
user_activity['activity_week'] = (
    user_activity['activity_date']
    - pd.to_timedelta(user_activity['activity_date'].dt.dayofweek, unit='d'))
# dayofweek: segunda = 0 ... domingo = 6

user_activity['cohort_lifetime'] = (
    (user_activity['activity_week'] - user_activity['first_activity_week'])
    / np.timedelta64(1, 'W')).astype('int')
```

**Retenção em Python:**

```python
cohorts = (user_activity.groupby(['first_activity_week', 'cohort_lifetime'])
           .agg({'user_id': 'nunique'}).reset_index())
initial = cohorts[cohorts['cohort_lifetime'] == 0][['first_activity_week', 'user_id']]
initial = initial.rename(columns={'user_id': 'cohort_users'})
cohorts = cohorts.merge(initial, on='first_activity_week')
cohorts['retention'] = cohorts['user_id'] / cohorts['cohort_users']

# atalho
cohorts['retention'] = cohorts['user_id'] / (
    cohorts.groupby('first_activity_week')['user_id'].transform('first'))
```

**Cancelamento em Python:**

```python
cohorts['churn_rate'] = cohorts.groupby('first_activity_week')['user_id'].pct_change()
```

`pct_change()` é "linha atual ÷ linha de cima − 1". O `groupby` impede que a primeira semana de uma coorte seja comparada com a última da coorte anterior. As linhas precisam estar em ordem de semana.

> [!ex] Lendo os dois mapas
> **Retenção, semana 1:** 69,9% na coorte mais antiga, 24,3% na mais nova. Os novos chegam menos interessados (tráfego pior? suporte?).
> **Cancelamento, semana 4:** dispara em várias coortes. Algo nessa fase espanta o usuário.

## Coorte comportamental

Agrupa os usuários pelo que **fizeram** no início (não só quando chegaram) e compara a retenção.

| App | Comportamento | Pergunta |
|---|---|---|
| Neuropicasso | Pediu ajuda mais de 5 vezes na 1ª semana | Quem pede ajuda fica mais? |
| Y.Music | Curtiu ao menos 1 música na 1ª semana | Quem curte volta mais? |
| CoffeeHome | Pediu 5 cafés em 30 dias e ganhou 1 | A promoção segura o cliente? |

```fluxo
Janela (ex.: 7 dias) → Contar a ação por usuário → Rotular yes / no / no_behavior → Comparar a retenção
```

```python
events['time_to_event'] = events['event_datetime'] - events['min_event_datetime']
filtered = events[(events['event_type'] == 'help') & (events['time_to_event'] < '7 days')]

count_by_user = filtered.groupby('user_id').agg({'event_datetime': 'count'}).reset_index()
count_by_user['is_target_behavior'] = count_by_user['event_datetime'] > 5   # 5 = mediana

target = count_by_user['is_target_behavior']
col = 'is_in_behavioral_cohort'
events.loc[events['user_id'].isin(count_by_user[target]['user_id']), col] = 'yes'
events.loc[events['user_id'].isin(count_by_user[~target]['user_id']), col] = 'no'
events[col] = events[col].fillna('no_behavior')
```

O limite pode vir de uma regra do negócio (5 cafés = 1 grátis) ou dos dados (a mediana divide em duas metades).

Para comparar, uma função calcula a retenção média por semana de vida e roda para cada grupo; `plt.subplots(1, 3, sharey=True)` coloca os três gráficos lado a lado **na mesma escala**.

> [!erro] Andar junto não é causar
> Quem pede 5 cafés já era um cliente animado antes da promoção. Grupos pequenos (≈ 50 usuários) oscilam muito. A análise aponta a hipótese; um teste A/B confirma.
